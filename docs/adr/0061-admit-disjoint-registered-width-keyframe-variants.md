# Admit disjoint registered width-keyframe variants without inventing precedence

A Module may retain one generated name for multiple different definitions of its same authored `@keyframes` name only when every distinct pair is statically proven never active together. The first bounded MVP proof accepts **unlayered**, singly wrapped, registered `@media` queries that are simple lowercase integer-pixel width bounds: one `(max-width: Apx)` and one `(min-width: Bpx)`, with `B > A` and both bounds between 0 and 100000 inclusive. Whitespace around the feature/colon is permitted; compound/nested queries, fractional/other units or features, absent/unregistered wrappers, same-direction bounds, equal/overlapping boundaries, different condition kinds, and layer combinations are not proven by this slice. Identical registrations in the same context retain their existing deduplication. A third different variant cannot pass the pairwise proof under these one-sided width-bound shapes.

Because the admitted definitions cannot coexist, their physical resource order cannot select a winner. Each retains its authored media wrapper, Module-local generated name and source attribution; static `animation-name` references continue to use that one name, leaving the browser to select whichever native definition is active. No new query-precedence rule, public configuration, preserved fallback or cross-kind/layer policy follows. Unproved different registrations still fail transactionally with `GSS1301` and retain last-known-good output, including when either wrapper is unregistered. The 100000px cap bounds numeric parsing/engine precision for this first proof rather than promising a general media-query solver. This is currently a **standalone Compiler and independent browser-oracle slice**: the Vite `gss({ adapter })` API does not expose condition registration, so the supported Vite host cannot yet supply these registered bounds. A host configuration port requires a separate owner decision; this ADR does not add one. Broader mutually exclusive conditions or multiple layer definitions require their own semantic and browser proof; [D020](../deferred-capabilities.md#d020--cross-kind-condition-precedence) remains deferred, and this slice does not complete S4 resource or condition acceptance.
